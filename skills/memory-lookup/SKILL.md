# Memory Lookup — 记忆库检索

## 定位

本 Skill 是 `memory-bank/` 记忆库根目录的统一检索入口。
记忆库内容 **已结构化为 markdown 文件**，无需向量数据库；本 Skill 用
「索引定位 + 定向精读 + Grep 兜底 + 外部 Skill 发现」分级检索替代 RAG。

维护的索引文件：`memory-bank/INDEX.md`（查询与更新都经过它）。

## 何时调用

- 用户问"以前遇到过类似问题吗 / 之前怎么处理的"
- 需要查阅项目规则、编码规范、枚举、接口、状态机、账套、i18n 等约定
- 需要追溯某个 story# 需求的实现细节、OpenSpec 文档位置
- 跨项目问题（shared 共享记忆）
- 开始新需求前想了解相关历史经验

## 分级检索协议

### 第 1 级：查 INDEX.md（必须先做）

读取 `memory-bank/INDEX.md`，按以下顺序匹配：

1. **跨项目主题速查**（第二节）——主题级定位，如"i18n → project-a/14 + project-b/31"
2. **标准文档矩阵**（第一节）——按项目 + 文档编号定位
3. **对话日志检索协议**（第三节）——确定 Grep 的目录范围

### 第 2 级：定向精读

根据索引定位，直接 `Read` 目标文件的相应章节。
**不要全文通读大文件**——先用 Grep 在文件内定位小节，再精读命中段落。

### 第 3 级：Grep 兜底（索引未命中时）

- 日志检索：`Grep "<关键词>" path="memory-bank/<项目>/99-dialogue-logs"`
- 全文检索：`Grep "<关键词>" path="memory-bank"`（范围大，慎用）
- 命中后**反向更新索引**：把新发现的主题补进 INDEX.md 对应小节

### 第 4 级：外部 Skill 发现（仅"想找现成 Skill"意图时）

当且仅当用户意图是"有没有现成的 Skill / 工具可用"（而非查询我们自己的历史经验）时，启用外部发现：

```bash
npx skills find <关键词>                  # 搜索 skills.sh 索引（60 万+ 开源 Skill）
npx skills find <关键词> --owner <org>    # 限定来源组织
npx skills add <repo> --list              # 只查看仓库内容，不安装
```

- skills.sh 为 Agent Skills 开放标准注册表（agentskills.io），SKILL.md 格式与本地兼容
- **安装前必须做供应链安全检查**：审查 SKILL.md 正文与 scripts/ 脚本有无网络外呼、凭据读取、混淆代码；优先选有持续维护、star 与下载量可验证的来源；拿不准就只 `--list` 查看不安装
- 发现值得引入的 Skill，报告给用户决策，**不自动安装**

## 输出规范

检索结果必须注明出处，格式：

```
📍 来源：memory-bank/<项目>/14-i18n-guide.md §语言包编码规则
   要点：<一句话结论>
```

- 引用规范原文时保持术语准确（枚举值、错误码、表名字段名不得改写）
- 检索不到时如实说"记忆库中未找到"，并建议是否值得新开文档记录
- **线索 vs 结论分诊（2026-10-21 新增）**：用户问的是业务逻辑/字段口径/权限现值/页面行为时，检索结果一律以"线索"形态输出（"某时点日志提到 xxx，位于某文件，建议对照现行代码"），不得直接包装成现值结论；代码逻辑类结论按下方时效红线复核通过后才能升级为结论

## 时效性红线（2026-10-21 海外联系人权限会话教训）

记忆库记录的是**写入时刻**的认知，代码和配置会持续演进。检索结果按下述规则分级处理：

1. **快照类内容（配置中心配置、生产行为、表结构、开关状态）**：输出时必须带上原文快照日期，并声明"该值为当时快照"。用户问的是"现在/生产现状"时，**禁止直接引用旧快照作答**，必须重新拉取现值后再给结论（配置中心参照 `ai-temp/config_check.py` 模式重新登录拉取）。快照距今超过 **2 周**即触发强制复核（与项目根目录 `AGENTS.md` 记忆结论分级规则一致）。
2. **代码逻辑类结论（决策树、分支判断、链路描述）**：日志距今超过约 **1 个月**、或期间该模块有过 story 改造的，一律视为"过期候选"——只能作为调查线索，必须打开现行代码核对（含 mapper/SQL 层）后才能作为结论输出。
3. **输出标注**：凡引用超过上述期限（快照 2 周 / 逻辑 1 个月）的结论，标注「📅 记忆快照：YYYY-MM-DD，待现行复核」；复核后改为「✅ 已对照现行代码/配置（YYYY-MM-DD）」。
4. 复核发现记忆库与现状不符时，当场修正原文或在当日对话日志中记录差异，不留过期结论在库中。

> 阈值统一约定（与 AGENTS.md 同源）：**快照 2 周、逻辑 1 个月**。两处规则不一致时以本表为准并提请维护者修正。

## 索引维护协议（重要）

记忆库是活库，索引必须同步维护，否则检索会退化成 Grep 全文扫：

| 触发动作 | 必须执行 |
|---------|---------|
| 归档对话日志到 `99-dialogue-logs/` | 文件名遵循 `YYYY-MM-DD_<主题>.md` 约定即视为已索引；开创新主题领域时在 INDEX 第二节补条目 |
| 新增/重排编号文档 | INDEX 第一节对应项目矩阵补行/调整 |
| 新增跨项目主题 | INDEX 第二节补条目 |
| 连续两次查询都靠 Grep 兜底才命中 | 立即把该主题补入索引（失修信号） |
| 发现索引条目与实际文件不符 | 当场修正，不留过期条目 |

## 与相关 Skill 的关系

- `shared-memory-bank`：负责记忆库**写入**（归档对话、更新待办）；本 Skill 负责**读出**（检索定位）。
- `skill-lookup`：检索 skills-ai 仓库的 Skill；本 Skill 检索工作记忆库，两者互补。
- `ops-interface-tracing`（链路排查类 Skill）：生产链路排查时，本 Skill 提供历史排查经验（如 `<项目>/24`、`<项目>/26`），链路排查 Skill 负责实际链路追踪。
