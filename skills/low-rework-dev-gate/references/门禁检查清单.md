# 门禁检查清单

## Gate 1 范围门

- [ ] 需求编号、名称、PRD、UI、父需求及依赖材料可定位。
- [ ] In Scope、Out of Scope、角色、权限和数据范围明确。
- [ ] 新增、编辑、查询、删除、启停、导入导出等动作已枚举。
- [ ] 状态及合法转换、重复请求、非法转换、终态明确。
- [ ] 核心计算、唯一性、默认值、排序、分页及数量上限明确。
- [ ] 历史数据、兼容策略、依赖变化和失败处理明确。
- [ ] 未决事项有负责人和决策状态，不存在影响设计的核心未决项。

## Gate 2 设计门

- [ ] 字段矩阵覆盖 UI、DTO、校验、领域对象、DB、VO、展示和测试。
- [ ] 动作矩阵覆盖权限、校验、幂等、锁、事务、写入、返回和重试。
- [ ] 状态矩阵覆盖前端按钮、后端防绕过及错误码。
- [ ] 故障矩阵覆盖并发、重复提交、锁超时、乐观锁冲突和部分写入。
- [ ] API 的请求、响应、分页、错误码和兼容策略完整。
- [ ] DDL 的字段、默认值、索引、删除策略、迁移和回滚完整。
- [ ] i18n、安全、日志、性能及数据隔离策略完整。
- [ ] `proposal/design/specs/API/DDL/tasks/验收场景` 交叉一致。
- [ ] 已执行 `openspec-audit` 首次全量审核并生成基线。
- [ ] 无 P0，核心 P1 已关闭或由负责人明确接受。

## Gate 3 实施门

- [ ] 实施前读取审核基线、项目规则和未关闭问题。
- [ ] 按 `tasks.md` 的可验收切片实施，没有脱离规范扩展范围。
- [ ] 修改共享契约前完成调用方和兼容性影响分析。
- [ ] 每个切片均执行对应编译、静态检查及正常/异常/边界测试。
- [ ] 实现中的计算、状态、权限、事务、锁、幂等与规范一致。
- [ ] 发现设计问题时已暂停编码、更新规范并完成差异复审。
- [ ] `tasks.md` 已记录规范映射、验证命令、结果和证据时间。

## Gate 4 提测门

- [ ] 后端聚合编译成功，目标单测和必要集成测试通过。
- [ ] 前端 build、lint 以及适用的类型/语法检查通过。
- [ ] `git diff --check` 通过，无调试代码和无关文件。
- [ ] API 请求、响应、分页、错误码、幂等完成联调。
- [ ] 权限、i18n、日志、安全、数据隔离完成检查。
- [ ] 并发、超时、重试、上限和历史兼容场景有验证证据。
- [ ] 验收标准、`tasks.md` 与实现逐项映射完成。
- [ ] 当前规范哈希与审核基线一致，或变化已完成差异复审。
- [ ] 无 P0、无未接受的提测阻断 P1、无无法解释的未验证项。

## 项目专项附加

### 业务后端服务（示例：服务 B）

- [ ] 先读项目 `AGENTS.md`（或项目共享规则）、对应 OpenSpec 和项目文档目录。
- [ ] 分页使用项目规定方案；Mapper 明确字段且带逻辑删除标记（如 `delete_flag`）。
- [ ] 保存及状态变更检查分布式锁、幂等和事务边界。
- [ ] 修改共享模型模块已按跨服务契约变更评估兼容性。
- [ ] 至少执行目标模块编译和相关单元测试。

### 业务前端项目（示例：系统 A 前端）

- [ ] API 统一经项目 API 层封装，页面未直接使用 HTTP 客户端。
- [ ] 移动端/PC 端组件、样式和权限方式符合现有项目惯例。
- [ ] 金额或系数计算未使用原生浮点运算。
- [ ] 多语言文案使用项目 i18n 机制（如 `$t`）。
- [ ] 执行适用的 lint 与生产构建。
