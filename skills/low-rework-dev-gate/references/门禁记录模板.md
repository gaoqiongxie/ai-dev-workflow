# 门禁记录模板

每个需求在 OpenSpec 变更目录下维护 `gate/gate-status.md`。首次执行时创建，后续只更新，不重复创建平行结论。

```markdown
# 研发门禁记录

## 基本信息
- 需求：<编号与名称>
- OpenSpec：<变更目录>
- PRD/UI：<材料路径>
- 当前状态：待澄清 / 可设计 / 文档待审 / 文档准入 / 实施中 / 编码完成 / 提测准入 / 发布准入
- 当前门禁：Gate 1 / Gate 2 / Gate 3 / Gate 4
- 更新时间：YYYY-MM-DD HH:mm

## 基线
- 审核基线：<audit-baseline.json 路径或无>
- 规范版本：<提交号或哈希摘要>
- 实现版本：<提交号或 working tree>
- 范围变化：无 / 有，说明

## 门禁检查
| 检查项 | 状态 | 证据 | 问题 ID |
|---|---|---|---|
| <检查项> | PASS / FAIL / BLOCKED / N/A | <文件、命令或测试结果> | <稳定 ID> |

## 阻断问题
| ID | 等级 | 根因 | 负责人 | 处理状态 | 复验依据 |
|---|---|---|---|---|---|
| GATE-P0-001 | P0 | <根因> | <角色> | open / accepted / closed | <依据> |

## 未验证项
| 项目 | 原因 | 风险 | 补验方式 |
|---|---|---|---|
| <项目> | environment_blocked / material_missing | <风险> | <方式> |

## 本轮结论
- 结论：通过 / 不通过 / 未完成
- 允许下一步：<只写一个合法状态迁移动作>
- 禁止动作：<不得越过的门禁>
```

## 状态规则

- `PASS`：已有可复现证据。
- `FAIL`：已验证不满足要求。
- `BLOCKED`：因环境或材料无法验证，不得视为通过。
- `N/A`：确实不适用，必须说明理由。
- 同一根因复用原问题 ID，问题指纹为：`业务对象 + 业务动作 + 根因 + 受影响契约`。
