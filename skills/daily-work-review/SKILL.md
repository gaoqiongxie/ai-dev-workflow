# 每日工作回顾生成 Skill

## 用途

基于当日对话日志，自动生成结构化的每日工作回顾文档，便于追溯、汇报和次日规划。

## 触发方式

用户说以下任一表述时触发：

- "帮我生成本日工作回顾"
- "生成今日回顾"
- "总结今天的工作"
- "写一下 daily review"
- "帮我汇总今天处理的事情"

## 输入参数

执行时必须向用户确认或从上下文推断：

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `date` | 回顾日期，格式 `YYYY-MM-DD` | 当天日期 |
| `project` | 项目标识，`project-a` / `project-b` / `both` | 当前对话所属项目 |
| `outputPath` | 回顾文件输出目录 | `memory-bank/<project>/99-dialogue-logs/daily-review/` |

## 执行步骤

### 步骤 1：定位对话日志

1. 根据 `project` 确定日志根目录：
   - project-a：`memory-bank/<project-a>/99-dialogue-logs/`
   - project-b：`memory-bank/<project-b>/99-dialogue-logs/`
   - both：同时读取上述两个目录
2. 筛选文件名以 `YYYY-MM-DD_` 开头的 `.md` 文件（不含 `daily-review/` 子目录本身）。
3. 如当日无日志，向用户确认是否仍要生成空回顾，或改用最近有日志的日期。

### 步骤 2：读取并提取关键信息

逐篇读取当日日志，提取以下字段：

- **涉及系统 / 模块**
- **需求追踪 ID**（story#123 / JIRA-456 / bug#789）
- **对话类型**（问题查询 / 需求评估 / 代码开发 / 方案讨论 / Bug 修复 / 代码审查）
- **用户原始诉求**（一句话概括）
- **关键结论**（条目式）
- **执行操作**（修改文件、执行命令、生成文档）
- **后续待办 / 风险**

### 步骤 3：生成回顾内容

按以下结构组织：

```markdown
# YYYY-MM-DD 工作回顾

## 一、今日处理事项概览

| 主题 | 涉及系统 | 模块 | 需求追踪 ID | 类型 | 状态 |
|------|----------|------|----------|------|------|
| ... | ... | ... | ... | ... | ... |

## 二、关键决策与结论

- **事项 A**：结论 1
- **事项 B**：结论 2

## 三、代码/文档变更清单

- 新增/修改文件：`path/to/file`
- 生成文档：`path/to/doc.md`
- 执行命令：`mvn clean compile ...`

## 四、待跟进项与风险

- [ ] 待确认项 / 责任人 / 期望时间
- [ ] 待测试项
- [ ] 潜在风险

## 五、明日建议重点

- 建议 1
- 建议 2
```

### 步骤 4：写入文件

1. 确保输出目录存在：
   ```
   memory-bank/<project>/99-dialogue-logs/daily-review/
   ```
2. 文件命名：`YYYY-MM-DD_daily-review.md`
3. 使用 UTF-8 编码写入。

### 步骤 5：汇报

向用户简要汇报：

- 当日共处理 N 个主题
- 回顾文件路径
- 需要特别关注的待办或风险（如有）

## 注意事项

- 回顾以"AI 辅助做了什么"和"产生了哪些决策/变更"为核心，不重复罗列原始对话。
- 同一主题跨越多天，回顾中引用前序日志文件名，避免信息冗余。
- 不涉及代码变更的纯咨询/排查对话，同样应纳入概览表。
- 严禁在回顾文件中保存密码、Token、真实业务数据明细等敏感信息。

## 示例输出

```markdown
# 2026-08-28 工作回顾

## 一、今日处理事项概览

| 主题 | 涉及系统 | 模块 | 需求追踪 ID | 类型 | 状态 |
|------|----------|------|----------|------|------|
| 订单导出增加自定义列 | 业务系统 A / 报表服务 | 订单管理 | story#12345 | 需求评估 | 待确认报表服务行为 |
| 归档规则更新 | 业务系统 A | 项目规范 | - | 规则更新 | 已完成 |

## 二、关键决策与结论

- story#12345 核心工作量在报表服务模板渲染；后端仅需调整导出参数组装。
- 在前端不动的前提下，纯后端可行方案为汇总扩展字段并注入虚拟汇总行。
- 项目主规则新增「对话记录与归档规范」，要求所有有价值对话必须生成日志。

## 三、代码/文档变更清单

- 修改规则：项目根 `.claude/CLAUDE.md`
- 同步规则：`memory-bank/<project>/00-memory-bank-rules.md`
- 新增 Skill：`.trae/skills/daily-work-review/SKILL.md`
- 生成日志：`memory-bank/<project>/99-dialogue-logs/2026-08-28_订单导出需求评估与归档规则更新.md`

## 四、待跟进项与风险

- [ ] 与报表服务团队确认模板动态渲染行为，再决定是否进入实施阶段。
- [ ] 新归档规则从今日起生效，后续每日对话结束需执行 Checklist。

## 五、明日建议重点

- 若报表服务行为确认，可启动 story#12345 实施。
- 继续按新规则归档当日对话。
```
